# План проверок на целевом железе

Цель: убедиться, что организм и llama.cpp работают на арендованном сервере (Dual EPYC 7K62, Zen 2), и подобрать числа для `config/territory.json` и `config/genome.json`. Критерии скорости взяты из `docs/20_roadmap.md`.

## Доступ

- Агент не вводит пароли и не входит на сервер сам. Команды выполняет человек: через VNC в терминале сервера или по SSH.
- Результат возвращается файлом: JSON-отчёты кладутся в `state/hw/` проекта (копирование, scp или общая папка). Агент читает их оттуда и решает, что дальше.
- Вариант с прямой работой агента: человек сам настраивает SSH по ключу (пароль не нужен) и сообщает, куда подключаться. Решение за человеком.
- Пароль к серверу в репозиторий и в документы не писать; после тестов сменить, он был показан в чате.
- Сервер арендован: порты наружу не открывать, llama-server слушает только 127.0.0.1 (`allow_network=false`).

## Этапы

| Этап | Что делается | Команда или файл | Критерий приёмки |
|---|---|---|---|
| H0 | Проект на сервере | `git clone https://github.com/RungeKut/organism`; `uv run --python 3.10 python -m unittest discover -s tests -t .` | 155+ тестов OK на Linux |
| H1 | Разведка железа | `uv run --python 3.10 python scripts/hw_probe.py` → `state/hw/probe_<host>.json` | видны узлы NUMA, объём и занятые слоты памяти, пропускная способность по узлам, излом кривой потоков |
| H2 | Сборка llama.cpp под Zen 2 | `uv run --python 3.10 python scripts/hw_llama.py` печатает команды; выполняет человек | `llama-bench --version` работает; сборка без AVX-512 |
| H3 | Скорости модели ~1B | матрица `llama-bench`: потоки 8–48 × NUMA none/node0/interleave; `hw_llama.py --parse файл.json` | генерация ≥ 10 ток/с; выбраны число потоков и режим NUMA |
| H4 | Организм с настоящей моделью | `scripts/llama_server.py --dry-run` → запуск; `python -m organism` без `--fake` | ответ от модели, `last_tps` > 0, слоты AIMD растут без роста `lag_ms` |
| H5 | Карта тела на железе | `python -m organism --body`; сон с калибровкой | `bodymap.json` с `calibration` (излом, пропускная способность) |
| H6 | Сон и поколения на модели | `generation_every_sleeps=1` один раз, смена только через `--approve` | `trial` не выполняет команды, `genome.json` меняется только по токену |
| H7 | Длительный прогон | tmux или systemd, 8–24 ч | аудит без нарушений, память процесса не растёт, журнал не раздувается, метрики воли пишутся |

## Что решаем по результатам

- Потоков на инстанс llama.cpp и режим NUMA: в какую сторону растёт скорость при 16, 24, 32 потоках.
- Нужна ли докупка памяти до 8 планок в сокете: сравнить полосу при 4 каналах с ожидаемой для 8.
- `max_llm_slots` и `headroom` для `territory.json`; значения вписывает человек.
- База ~1B: проверить русский токенизатор на реальной модели.
- Нужно ли отдельное ядро под рефлексы и «Тело».

## Остановка и безопасность

- Любой этап прерывается без потерь: состояние в `state/`, точка возобновления в `docs/50_status/STATE.md`.
- Команды организма ограничены `exec_allowlist`; на сервере его не расширять без явного решения человека.
- Результаты замеров на этой машине (6 ядер, 8 ГБ) для сервера не годятся: все числа снимаются на сервере.
