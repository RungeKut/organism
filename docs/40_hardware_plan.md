# План проверок на целевом железе

Цель: убедиться, что организм и llama.cpp работают на арендованном сервере (Dual EPYC 7K62, Zen 2), и подобрать числа для `config/territory.json` и `config/genome.json`. Критерии скорости взяты из `docs/20_roadmap.md`.

## Факты о сервере (сняты 2026-10-27, `result/`)

- ОС: Windows 10 Pro 19045, не Linux. Там же работает VMware Workstation с ВМ человека: замеры снимать, когда ВМ простаивают.
- Процессоры: 2 × EPYC 7K62 (Zen 2, AVX2, без AVX-512), 96 ядер / 192 логических потока, L3 192 МБ на сокет.
- Память: 4 × 64 ГБ DDR4-3200 ECC (работает на 2933 МТ/с), 256 ГБ. Все планки на сокете P0, каналы A, B, E, F (4 из 8). У сокета P1 памяти нет: его 96 потоков ходят в память P0.
- Потолок полосы P0: 4 × 2933 МТ/с × 8 Б ≈ 94 ГБ/с (расчёт, не замер). Для модели ~1B в Q4 (~0.7 ГБ) верхняя граница генерации порядка 100 ток/с; реальное число даст замер.
- На Windows больше 64 логических процессоров делятся на группы; проверить, сколько потоков llama.cpp реально использует.
- Включены компоненты WSL, Ubuntu скачана; до перезагрузки (делает человек) не активна. WSL2 — виртуалка: NUMA и слоты памяти изнутри не видны, замеры скорости годятся.
- Установлен OpenSSH Server (порт 22). Наружу не открывать; вход только по ключу.

## Доступ

- Агент не вводит пароли и не входит на сервер сам. Команды выполняет человек.
- Обмен: агент кладёт `go.md` в корень проекта, человек выполняет шаги, кладёт результат в `result/` и переносит `go.md` туда же.
- Код на сервер: `outbox/organism-hw.zip` (собирается `git archive`, в git не входит). Публикация ветки на GitHub — только по команде человека.
- Пароль к серверу в репозиторий и в документы не писать; после тестов сменить, он был показан в чате.

## Что решаем по результатам

- Потоков на инстанс llama.cpp и привязка к сокету: в какую сторону растёт скорость при 16, 24, 48, 96 потоках.
- Нужна ли докупка памяти до 8 планок в сокете и установка памяти в P1: сравнить полосу при 4 каналах с ожидаемой для 8.
- Где живёт боевой организм: Windows напрямую (код на stdlib) или WSL/голый Linux.
- `max_llm_slots` и `headroom` для `territory.json`; значения вписывает человек.
- База ~1B: проверить русский токенизатор на реальной модели.
- Нужно ли отдельное ядро под рефлексы и «Тело».

## Остановка и безопасность

- Любой этап прерывается без потерь: состояние в `state/`, точка возобновления в `docs/50_status/STATE.md`.
- Команды организма ограничены `exec_allowlist`; на сервере его не расширять без явного решения человека.
- Загрузки (релиз llama.cpp, модель) выполняет человек; агент называет источник и размер.
